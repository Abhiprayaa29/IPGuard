## 4. Backend Security Audit

Audit menyeluruh memverifikasi bahwa:
- Tidak ada private key yang disimpan, diterima, atau dikirimkan oleh backend.
- Seluruh verifikasi kegagalan beroperasi secara *fail-closed*.
- Parsing X.509 ASN.1 DER menggunakan `validate=True` RFC 4648 strict decoding.
- Session status transition bersifat satu arah (irreversible state machine).

---

## 5. PostgreSQL Race Condition Verification (SEC-01)

- **Mekanisme:** Menggunakan `with_for_update()` pada kueri seleksi SQLAlchemy 2.0 di dalam transaksi aktif `verify_session_signature`, `register_device`, dan `mark_session_scanned`.
- **Hasil Uji:** [`backend/tests/test_concurrency_race.py`](../backend/tests/test_concurrency_race.py) menjalankan pengujian multi-threaded dengan `ThreadPoolExecutor` terhadap database PostgreSQL lokal.
- **Bukti:** Tepat 1 permintaan berhasil memperoleh status HTTP 200 `APPROVED` (atau HTTP 201 Created), sedangkan 3 permintaan simultan lainnya ditolak dengan HTTP 400 `session_already_consumed`. Kondisi state database tetap atomik dan konsisten.

---

## 6. Origin Validation Results (SEC-03)

- **Mekanisme:** Modul [`backend/app/services/origin.py`](../backend/app/services/origin.py) melakukan normalisasi scheme (`http`/`https`), lowercase hostname, pembersihan port standar (80/443), serta penolakan path, query string, dan fragment.
- **Whitelist Enforcement:** Origin divalidasi terhadap `trusted_origin_list` dan diikat ke `session.client_origin`. Canonical payload yang diverifikasi wajib menggunakan origin tersimpan tersebut.
- **Hasil Uji:** 18 skenario uji lulus 100% pada [`backend/tests/test_origin_validation.py`](../backend/tests/test_origin_validation.py), termasuk penolakan suffix attacks (`localhost:5173.attacker.com`), skema berbahaya (`javascript:`), dan domain spoofing.

---

## 7. Device Protection Results (SEC-04)

- **Mekanisme:** Endpoint `GET /api/v1/auth/devices` diproteksi oleh dependency guard `require_dev_admin_access`.
- **Hasil Uji:** Pada [`backend/tests/test_device_protection.py`](../backend/tests/test_device_protection.py):
  - Akses tanpa header rahasia -> HTTP 401 `unauthorized_admin_access`.
  - Akses dengan kunci tidak valid -> HTTP 401 `unauthorized_admin_access`.
  - Akses dengan `X-Dev-Admin-Key` valid di development -> HTTP 200 OK dengan daftar perangkat.
  - Simulasi konfigurasi produksi (`APP_ENV=production`) -> HTTP 403 `endpoint_disabled_in_production` (terkunci mutlak).

---

## 8. ECDSA Verification Audit

- **Algoritma:** NIST P-256 (`secp256r1`) dengan SHA-256 digest (`SHA256withECDSA`).
- **Encoding Signature:** ASN.1 DER sequence `(r, s)` berukuran 64–72 bytes.
- **Konsistensi Fingerprint:** SHA-256 atas raw bytes SubjectPublicKeyInfo menghasilkan 95 karakter hex bertitik-dua (`AA:BB:...:11:22`), identik 100% dengan implementasi Android Keystore `ExportedPublicKey.sha256Fingerprint`.
- **Hasil Uji:** 12 pengujian kriptografi pada [`backend/tests/test_crypto_verifier.py`](../backend/tests/test_crypto_verifier.py) lulus 100%.
