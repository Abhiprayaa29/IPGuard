## 1. Executive Summary

Laporan ini menyajikan audit keamanan menyeluruh dan verifikasi langsung pada perangkat fisik Android (Samsung Galaxy A54 5G SM-A546E, Android 16 / API 36) terhadap implementasi **M2.3-A Android Keystore & Device Signing Key Foundation**.

### Ringkasan Temuan Utama:
1. **Verifikasi Fisik 100% Berhasil**: Rangkaian 12 skenario pengujian Android Instrumentation (`DeviceKeyPhysicalInstrumentationTest`) dieksekusi langsung pada perangkat fisik melalui ADB dan seluruhnya lulus (12/12 passed dalam 39 detik).
2. **Hardware-Backed TEE Terkonfirmasi**: Kunci signing terbukti dihasilkan dan disimpan di dalam **Trusted Execution Environment (TEE)** (`KeyInfo.securityLevel = 1` / `KeyProperties.SECURITY_LEVEL_TRUSTED_ENVIRONMENT`, `isInsideSecureHardware = true`).
3. **Private Key Non-Exportable**: Dikonfirmasi secara nyata pada runtime heap perangkat bahwa `privateKey.encoded == null` dan class private key adalah `android.security.keystore2.AndroidKeyStoreECPrivateKey`.
4. **Persistensi Tervalidasi Nyata**: Kunci berhasil diuji persistensinya melalui siklus force-stop (`am force-stop com.ipguard.authenticator`), cold restart, dan reload. SHA-256 fingerprint sebelum dan sesudah force-stop terbukti **100% identik**.
5. **Temuan Kritis Kebijakan Autentikasi (Pre-Flight Biometric Check)**: Perangkat fisik memiliki Secure Lock Screen aktif (`isDeviceSecure = true`, PIN/Pola aktif), namun sensor biometrik sidik jari belum memiliki template terdaftar (`enrolled print count = 0`), sementara Face Unlock hanya berstatus Class 2 (`BIOMETRIC_WEAK`). Jika M2.3-B menggunakan `BiometricPrompt.CryptoObject` dengan durasi 0 (per-operasi), penandatanganan akan mewajibkan pendaftaran sidik jari Class 3 (`BIOMETRIC_STRONG`). Keputusan dan mitigasi arsitektur telah dirumuskan.

## 2. Existing Implementation Review

Dilakukan audit mendalam terhadap seluruh call-site dan komponen pengelola kunci:

- **`DeviceKeyManager.kt`**:
  - `generateSigningKey(requireUserAuthentication: Boolean)`: Mengonfigurasi `KeyGenParameterSpec` dengan kurva `secp256r1`, digest `SHA-256`, dan tujuan `PURPOSE_SIGN | PURPOSE_VERIFY`.
  - `ensureSigningKey(requireUserAuthentication: Boolean)`: Bersifat idempoten; memeriksa eksistensi kunci terlebih dahulu sebelum membuat kunci baru.
  - `getPrivateKey()`: Mengambil handle entry Keystore dan secara aktif memverifikasi penegasan `privateKey.encoded == null`. Jika non-null, melempar `KeySecurityViolationException`.
  - `deleteSigningKey()`: Menghapus alias secara eksplisit tanpa penghapusan otomatis siluman saat terjadi kegagalan.
- **`AuthenticatorViewModel.kt`**:
  - `generateSigningKey(requireUserAuth: Boolean = true)`: Secara default **selalu** mewajibkan autentikasi pengguna (`true`).
  - Tidak ditemukan jalur kode produksi yang menghasilkan signing key tanpa perlindungan `setUserAuthenticationRequired(true)`. Flag `false` hanya tersedia untuk pengujian isolasi internal.

## 3. Authentication Policy Compatibility

Diuji dan dievaluasi dua strategi kebijakan autentikasi untuk Android Keystore:

| Parameter Evaluasi | Strategy A: Strong Biometric, Per-Operation | Strategy B: Biometric / Credential with Time Window |
|---|---|---|
| **Konfigurasi KeyGen** | `timeout = 0`, `AUTH_BIOMETRIC_STRONG` | `timeout > 0` (misal 30s), `AUTH_BIOMETRIC_STRONG \| AUTH_DEVICE_CREDENTIAL` |
| **Integrasi Biometric** | `BiometricPrompt.CryptoObject(signature)` | `BiometricPrompt` tanpa `CryptoObject` |
| **Otorisasi Penandatanganan** | Wajib biometrik Class 3 setiap kali payload ditandatangani | Kunci terbuka selama window waktu setelah autentikasi sukses |
| **Resiko Keamanan** | Sangat Rendah (Zero window of vulnerability) | Sedang (Proses lain/thread lain dapat menggunakan kunci selama window aktif) |
| **Fallback PIN/Password** | Tidak didukung untuk `CryptoObject` auth-per-operation pada API 30+ | Didukung penuh via `DEVICE_CREDENTIAL` |
| **User Experience** | Interaktif, setiap approval meminta sidik jari | Cepat jika dalam 30 detik melakukan multiple signing |

### Rekomendasi Arsitektur untuk IPGuard:
IPGuard adalah sistem otorisasi aset digital bernilai tinggi. **Strategy A** merupakan standar emas keamanan. Namun, untuk mencegah error saat pengguna belum mendaftarkan sidik jari (seperti pada kondisi HP uji coba saat ini), aplikasi wajib melakukan pemeriksaan pre-flight:
1. Periksa `BiometricManager.canAuthenticate(BIOMETRIC_STRONG)`.
2. Jika berstatus `BIOMETRIC_ERROR_NONE_ENROLLED`, tampilkan prompt edukatif agar pengguna mendaftarkan sidik jari di Settings Android sebelum melakukan enrollment perangkat.

## 4. CryptoObject Compatibility

Pada submilestone M2.3-B, penandatanganan challenge dilakukan menggunakan:
```kotlin
val signature = Signature.getInstance("SHA256withECDSA")
signature.initSign(deviceKeyManager.getPrivateKey())
val cryptoObject = BiometricPrompt.CryptoObject(signature)
biometricPrompt.authenticate(promptInfo, cryptoObject)
```

### Analisis Kompatibilitas Android Platform:
1. **Aturan Auth-Per-Operation (`timeout = 0`)**:
   - Android Keystore mengharuskan auth token kriptografis per-operasi berasal dari sensor hardware biometrik Class 3 (`BIOMETRIC_STRONG`).
   - Token dari PIN/Password/Pola (`DEVICE_CREDENTIAL`) adalah *time-based timestamp token*, bukan per-operation token. Oleh karena itu, pada Android 11+ (API 30+), `BiometricPrompt` yang membawa `CryptoObject` dengan kunci auth-per-operation **tidak dapat** diselesaikan menggunakan PIN/Password jika prompt dikonfigurasi hanya untuk `BIOMETRIC_STRONG`.
2. **Class 2 Biometrics (Face Unlock)**:
   - Dumpsys sensor perangkat menunjukkan kamera depan Samsung Galaxy A54 berstatus `modality 8`, `strength 255` (`BIOMETRIC_WEAK` / Class 2).
   - Sensor Class 2 **tidak memenuhi syarat** untuk mengotorisasi `CryptoObject` Android Keystore.
   - Penandatanganan challenge pada M2.3-B wajib menggunakan sensor sidik jari optik (`modality 2`, `strength 15` / `BIOMETRIC_STRONG`).

## 5. Biometric Invalidation Analysis

Panggilan:
```kotlin
builder.setInvalidatedByBiometricEnrollment(true)
```

### Temuan Audit & Implikasi Keamanan:
1. **Perlindungan Terhadap Pendaftaran Biometrik Baru**:
   - Jika pengguna atau pihak lain yang meminjam HP mendaftarkan sidik jari baru ke pengaturan Android, Keystore secara permanen menandai kunci penandatangan sebagai tidak valid.
2. **Exception Runtime**:
   - Pemanggilan `signature.initSign(privateKey)` selanjutnya akan melempar `android.security.keystore.KeyPermanentlyInvalidatedException`.
3. **Prosedur Pemulihan (Recovery Protocol)**:
   - Kunci yang sudah permanently invalidated **tidak dapat dipulihkan**.
   - Aplikasi IPGuard tidak boleh crash. Aplikasi harus menangkap `KeyPermanentlyInvalidatedException`, memberi tahu pengguna bahwa kredensial biometrik sistem telah berubah, dan meminta pengguna melakukan pendaftaran ulang perangkat (Device Re-enrollment) ke backend IPGuard.

## 9. KeyInfo and Hardware Security Assessment

### Hasil Pengukuran Aktual `KeyInfo` (Samsung SM-A546E):
- `KeyInfo.getSecurityLevel()`: `1` $\rightarrow$ Dipetakan secara tepat ke `KeySecurityLevel.TRUSTED_ENVIRONMENT`.
- `KeyInfo.isInsideSecureHardware`: `true`.
- `KeyInfo.getKeySize()`: `256` bit.
- `KeyInfo.getPurposes()`: `12` (`KeyProperties.PURPOSE_SIGN (4) | KeyProperties.PURPOSE_VERIFY (8)`).
- `KeyInfo.getDigests()`: `["SHA-256"]`.

### Audit Klaim Keamanan Perangkat Keras:
1. **TEE vs StrongBox**: Perangkat Samsung Galaxy A54 mengeksekusi Keystore di dalam ARM TrustZone / Trusted Execution Environment (TEE). Perangkat ini **tidak memiliki** chip terisolasi sekunder StrongBox Keymaster (`KeyProperties.SECURITY_LEVEL_STRONGBOX`). Dokumentasi secara akurat mencatat tingkat keamanan sebagai **TEE**, bukan StrongBox.
2. **Batas Validitas Platform**: Nilai TEE ini diperoleh dari API lokal Android platform. Ini membuktikan isolasi hardware lokal, namun **bukan pengganti Remote Key Attestation** yang diverifikasi server.

## 12. Recommended Authentication Architecture

Untuk menjamin kelancaran transisi ke milestone M2.3-B:

```text
                               +---------------------------------------------+
                               |        IPGuard Mobile Authenticator         |
                               +---------------------------------------------+
                                                      │
                                                      ▼
                               +---------------------------------------------+
                               |     Pre-Flight Biometric Capability Check   |
                               |  BiometricManager.canAuthenticate(STRONG)   |
                               +---------------------------------------------+
                                      │                              │
                     BIOMETRIC_SUCCESS│                              │BIOMETRIC_ERROR_NONE_ENROLLED
                                      ▼                              ▼
             +----------------------------------+          +----------------------------------+
             | Generate Key (timeout = 0)       |          | Inform User to Enroll Fingerprint|
             | Sign Payload via CryptoObject    |          | in Android System Settings       |
             +----------------------------------+          +----------------------------------+
```

1. **Pre-flight Check**: Sebelum pendaftaran kunci perangkat di M2.3-B, periksa apakah pengguna sudah memiliki sidik jari terdaftar di Android. Jika belum, arahkan pengguna ke menu Settings sistem.
2. **Catch `KeyPermanentlyInvalidatedException`**: Tambahkan handling eksplisit untuk meminta re-enrollment jika pengguna mengubah sidik jari sistem.

## 13. M2.3-B Readiness Decision

### Keputusan: **READY WITH CONDITIONS**

Fondasi Android Keystore M2.3-A telah terbukti kokoh, aman, idempoten, persisten, dan terisolasi di hardware TEE pada perangkat fisik nyata. Submilestone M2.3-B dapat segera dimulai dengan memenuhi kondisi prasyarat berikut:
1. **Menambahkan dependensi `androidx.biometric:biometric-ktx`** pada `app/build.gradle.kts`.
2. **Menyediakan Pre-Flight Check** untuk memastikan sidik jari Class 3 terdaftar sebelum menginisialisasi `CryptoObject`.
3. **Menyediakan penanganan `KeyPermanentlyInvalidatedException`** untuk alur re-enrollment identitas perangkat.
