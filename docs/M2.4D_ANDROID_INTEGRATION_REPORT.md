## 1. Executive Summary

Milestone 2.4-D establishes the end-to-end integration between the physical Android Authenticator (`mobile-authenticator`) and the FastAPI backend + PostgreSQL engine.

Prior to M2.4-D:
- The Android Authenticator possessed hardware Keystore ECDSA P-256 signing with `DEVICE_CREDENTIAL` and `BIOMETRIC_STRONG` policies (M2.3-B), but operated purely in a local preview mode with no network layer and unvalidated QR scans.
- The Backend possessed cryptographic verification of NIST P-256 signatures, single-use nonce challenges with row-level locking (`SELECT FOR UPDATE`), and Anti QR-Jacking protection with `browser_channel_token` isolation (M2.4-B and M2.4-C).

Milestone 2.4-D bridges these systems with:
1. **Strict QR Payload Parser:** Rejects malformed JSON, unsupported schemas, invalid tokens/nonces, non-standard origins, expired timestamps (>180s), and any payload attempting to smuggle browser-bound secrets.
2. **Anti QR-Jacking Invariant Enforcement (SEC-02):** Android authenticators never receive, request, or handle `browser_channel_token`. The QR payload carries strictly `{version, type, session_token, nonce, origin, timestamp}`.
3. **Secure Asynchronous Networking:** Coroutine-based OkHttp client with strict timeouts, structured error handling, zero credential leakage, and debug-only cleartext allowance strictly for local reverse-proxy development (`127.0.0.1` / `localhost` via `adb reverse`).
4. **App-Scoped Device Identity:** Privacy-preserving device ID generation (`ipguard-dev-<uuid>`) persisted in private `SharedPreferences`, avoiding IMEI or hardware identifiers.
5. **Real User Consent & Approval Flow:** Scanned QR challenges trigger the full consent pipeline:
   - Web origin and session details presented to user.
   - User approval prompts Android `BiometricPrompt` / device PIN.
   - Keystore signs canonical payload (`session_token:nonce:origin:timestamp`).
   - Submits signature to backend `POST /api/v1/auth/sessions/{session_token}/verify` or `POST /api/v1/auth/devices/register`.
   - Results screen renders real-time backend confirmation or rejection.
6. **Physical Device Verification:** Successfully compiled, packaged (`app-debug.apk`), deployed, and verified on physical Samsung Galaxy A54 5G running Android 16 (SDK 36) via USB/ADB.

## 2. Architecture & Implementation Details

### 2.1 QR Authentication Payload Parser
- **Package:** `com.ipguard.authenticator.security.qr`
- **Classes:**
  - `QrSessionType`: Enum supporting `AUTHENTICATION` and `ENROLLMENT`.
  - `QrAuthPayload`: Validated payload containing `version`, `type`, `sessionToken`, `nonce`, `origin`, and `timestamp`. Exposes `buildCanonicalPayload()` and `getCanonicalBytes()` ensuring 100% byte-for-byte fidelity with backend `crypto.py`.
  - `QrPayloadValidationResult`: Sealed hierarchy (`Valid`, `Invalid(reason, errorCode)`).
  - `QrAuthPayloadParser`: Enforces RFC 6454 origin validation, strict 64-hex token/nonce matching (`^[a-fA-F0-9]{64}$`), 2048-byte limit, and rejects any payload containing forbidden fields (`browser_channel_token`, `access_token`, `private_key`, `secret`).

### 2.2 Asynchronous Networking Layer
- **Package:** `com.ipguard.authenticator.network`
- **Library:** OkHttp 4.12.0 with Kotlin Coroutines (`Dispatchers.IO`).
- **Interfaces & Classes:**
  - `ApiResult<T>`: Sealed outcome (`Success(data)`, `HttpError(code, errorCode, message)`, `NetworkError(message)`).
  - `AuthApiService`: Interface exposing `scanSession()`, `verifySession()`, and `registerDevice()`.
  - `OkHttpAuthApiService`: Implementation with 10s connect, 15s read/write timeouts, configured for UTF-8 JSON payloads and safe error parsing.
  - `DeviceIdManager`: Thread-safe UUID-based device identification.

### 2.3 Network Security Configuration
- **Production (`app/src/main/AndroidManifest.xml`):** `usesCleartextTraffic="false"` strictly preserved.
- **Debug Variant (`app/src/debug/res/xml/network_security_config.xml`):** Permits cleartext HTTP strictly for `127.0.0.1`, `localhost`, and `10.0.2.2`, applied via `app/src/debug/AndroidManifest.xml`.
- **ADB Reverse Port Forwarding:** Development runs over `adb reverse tcp:8000 tcp:8000`, routing phone requests to `http://127.0.0.1:8000/api/v1` without exposing backend ports to the local network or requiring cleartext across public interfaces.

### 2.4 Presentation & UI State Machine
- **`AuthenticatorUiState`:** Extended with `AuthFlowStep` (`IDLE`, `SCANNING`, `AWAITING_USER_CONSENT`, `AWAITING_DEVICE_AUTHENTICATION`, `SUBMITTING_BACKEND`, `COMPLETED_APPROVED`, `COMPLETED_REJECTED`, `FAILED`) and `ActiveAuthSessionState`.
- **`AuthenticatorViewModel`:**
  - `onQrCodeScanned()`: Parses raw barcode string, notifies backend `scanSession()` in background, and navigates to consent.
  - `approveAndExecuteAuth()`: Initiates `DeviceSigningAuthenticator` BiometricPrompt, retrieves ECDSA signature, constructs `VerifySessionRequest` or `RegisterDeviceRequest`, and submits to backend.
  - `cancelActiveSession()`: Clears active session state on user rejection or cancellation.
- **Composables Updated:**
  - `QrScannerScreen`: Delivers decoded string to `onScanComplete: (String) -> Unit`.
  - `AuthenticationRequestScreen`: Displays verified origin, service, browser, and adapts dynamically to `ENROLLMENT` vs `AUTHENTICATION`.
  - `ApprovalScreen`: Displays authentication policy, signing operation, and executes backend submission.
  - `ResultScreen`: Dynamically indicates backend verification status and errors.
