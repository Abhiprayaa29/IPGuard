## 1. Ringkasan Eksekutif Revisi Kebijakan

Milestone M2.3-B merevisi kebijakan otorisasi biometrik pada IPGuard Authenticator untuk mengatasi kendala perangkat keras fisik di dunia nyata:
- **Kondisi Perangkat Fisik:** Pada perangkat uji fisik Samsung Galaxy A54 5G (`SM-A546E`, Android 16 / API 36), sensor sidik jari optik di bawah layar tidak berfungsi setelah penggantian layar (screen replacement), sehingga sidik jari yang terdaftar adalah 0 (`prints count = 0`, status `BIOMETRIC_ERROR_NONE_ENROLLED`).
- **Penolakan Persyaratan Kaku (Non-Mandatory Fingerprint):** Aplikasi IPGuard **TIDAK BOLEH** mewajibkan sidik jari atau memblokir pengguna dari penggunaan aplikasi autentikator ketika sensor biometrik sidik jari rusak atau tidak terdaftar.
- **Kebijakan Adaptif Multi-Tier:**
  1. **Tier 1 — `BIOMETRIC_STRONG` (Class 3 Biometric):** Bersifat opsional. Digunakan jika perangkat keras tersedia dan pengguna telah mendaftarkan biometrik kuat.
  2. **Tier 2 — `DEVICE_CREDENTIAL` (PIN, Pattern, Password):** Menjadi metode otorisasi utama (*primary authorizer*) pada perangkat Galaxy A54 saat ini.
  3. **Tier 3 — `BIOMETRIC_WEAK` (Class 2 / Face Unlock):** Hanya untuk kenyamanan UI non-kriptografis. **Dilarang keras** mengotorisasi penggunaan private key Android Keystore.
  4. **Tier 4 — ML Kit Face Gate:** Tetap berupa pengecekan kehadiran visual (*framing presence check*), bukan pembuktian identitas, dan tidak memiliki wewenang otorisasi kriptografi.
- **Dukungan Platform Android Keystore & BiometricPrompt:**
  - Kunci ECDSA P-256 (`ipguard_device_signing_v1`) dikonfigurasi dengan `setUserAuthenticationRequired(true)` dan bitmask parameter `setUserAuthenticationParameters(0, KeyProperties.AUTH_BIOMETRIC_STRONG or KeyProperties.AUTH_DEVICE_CREDENTIAL)`.
  - Pada Android 16 (API 36) dengan `androidx.biometric:biometric-ktx:1.2.0-alpha05`, kombinasi `BiometricPrompt.PromptInfo.Builder.setAllowedAuthenticators(BIOMETRIC_STRONG or DEVICE_CREDENTIAL)` bersama `BiometricPrompt.CryptoObject` didukung penuh oleh platform tanpa melempar exception `IllegalArgumentException`.
  - Otorisasi per-operasi (*auth-per-use*, duration 0 detik) terbukti berhasil mengeksekusi penandatanganan ECDSA secara langsung saat pengguna mengautentikasi melalui kredensial perangkat (PIN) tanpa mengekspos private key (`encoded == null`).

## 3. Kebijakan Autentikasi Aktual yang Diterapkan

1. `DeviceAuthenticationPolicy.kt`: Mendeteksi kapabilitas perangkat dan menentukan jalur otorisasi primer secara deterministik.

## 9. Analisis Keamanan dan Trade-Off Fallback

| Aspek Keamanan | Implementasi M2.3-B | Evaluasi Ancaman & Mitigasi |
|---|---|---|
| **Pencegahan Bypass Otorisasi** | Otorisasi per-operasi (`setUserAuthenticationParameters(0, ...)`) | Private key Keystore tetap terkunci di TEE sampai OS mengonfirmasi verifikasi PIN/Biometrik melalui Gatekeeper/BiometricPrompt. Upaya penandatanganan langsung tanpa otorisasi terbukti ditolak dengan `UserNotAuthenticatedException` (AUTH-09). |
| **Kelemahan PIN vs Biometrik** | PIN rentan terhadap pengintaian visual (*shoulder surfing*) | PIN diproses oleh secure keyguard dialog sistem Android (bukan view aplikasi pihak ketiga). Limitasi salah tebak dikendalikan oleh hardware rate-limiter TEE (exponential backoff). |
| **Pengecualian Class 2 Face Unlock** | Face unlock kamera 2D dilarang mengotorisasi Keystore | Mencegah serangan spoofing foto/video 2D yang dapat membobol face unlock pada Samsung A54. Kunci hanya merespons Gatekeeper PIN atau Class 3 Strong Biometric. |
| **Non-Exportability Kunci** | `privateKey.encoded == null` | Kunci tidak dapat disalin keluar dari hardware, baik saat menggunakan PIN maupun biometrik. Keamanan identitas perangkat tetap setara hardware security. |
| **Kompatibilitas Versi OS** | Android 11+ (`Build.VERSION_CODES.R`) | `AUTH_DEVICE_CREDENTIAL` dengan `CryptoObject` didukung resmi pada API 30+. Pada API < 30, platform mengharuskan validitas berbasis durasi (window auth), namun Galaxy A54 berjalan pada Android 16 (API 36) yang mendukung per-operation crypto credential. |

## 10. Rekomendasi untuk M2.4 (QR Parsing, Challenge Validation, Enrollment)

1. **Payload Enrollment Format (M2.4):**
   - Saat proses binding perangkat (*enrollment*), kirimkan:
     ```json
     {
       "device_id": "ipguard_a54_device",
       "public_key_x509": "<Base64 SubjectPublicKeyInfo>",
       "public_key_fingerprint": "<SHA-256 Hex>",
       "security_level": "TRUSTED_ENVIRONMENT",
       "auth_mode": "DEVICE_CREDENTIAL_PRIMARY"
     }
     ```
2. **Challenge-Response Sign-In Flow:**
   - Backend IPGuard FastAPI menghasilkan challenge nonce kriptografis acak (misal 32-byte UUID v4 / SecureRandom) yang disematkan dalam QR code.
   - Authenticator memindai QR, mengekstrak challenge, meluncurkan `DeviceSigningAuthenticator.authenticateAndSign(activity, challenge)`.
   - Mengirimkan signature Base64 kembali ke backend untuk diverifikasi menggunakan public key yang terdaftar.
3. **Format Serialisasi Signature:**
   - ECDSA di Android Keystore menghasilkan format standar ASN.1 DER (`SEQUENCE { r INTEGER, s INTEGER }`). Pastikan backend FastAPI menggunakan `cryptography.hazmat.primitives.asymmetric.ec.ECDSA(hashes.SHA256())` yang secara native menerima format DER.
