## 1. Tujuan M2.3-A

Milestone M2.3-A bertujuan membangun fondasi identitas kriptografis perangkat Android native IPGuard Authenticator menggunakan **Android Keystore Provider**:

1. **Penerbitan Kunci Asimetris Perangkat (Device Identity Keypair)**:
   - Setiap perangkat Android yang menjalankan IPGuard Authenticator memiliki pasangan kunci asimetris berbasis kurva eliptik ECDSA P-256 (`secp256r1`).
   - Private key dihasilkan dan disimpan langsung di dalam ruang penyimpanan aman Android Keystore (`AndroidKeyStore`).
2. **Perlindungan Private Key Tanpa Ekspor (Strict Non-Exportability)**:
   - Private key tidak pernah dapat diekspor (`privateKey.encoded == null`).
   - Private key tidak pernah meninggalkan hardware/keystore boundary, tidak ditulis ke flash disk, SharedPreferences, SQLite, DataStore, memory dumps, QR code, atau dikirim melalui jaringan.
3. **Ekspor Public Key Standar (X.509 SubjectPublicKeyInfo)**:
   - Public key diekstrak dari sertifikat Keystore dan di-encode ke format standar X.509 `SubjectPublicKeyInfo` berbasis Base64 tanpa pemisah baris (`NO_WRAP`), siap dikonsumsi oleh backend Python FastAPI (`cryptography` library) pada fase enrollment M2.3-B/M2.4.
4. **Inspeksi Metadata Keamanan Perangkat (Platform Security Level Discovery)**:
   - Memeriksa kapabilitas perangkat lokal secara langsung melalui `KeyInfo` untuk mengetahui apakah kunci berada di TEE (Trusted Execution Environment), StrongBox Keymaster, atau Software fallback.
5. **Konfigurasi Kebijakan Autentikasi Pengguna (User Authentication Policy)**:
   - Kunci dikonfigurasi dengan flag `setUserAuthenticationRequired(true)` dan otorisasi per operasi, menyiapkan landasan kriptografi yang kokoh untuk otorisasi lokal melalui `BiometricPrompt` pada M2.3-B tanpa menurunkan postur keamanan.
6. **Idempotensi dan Pencegahan Kehilangan Identitas**:
   - Operasi inisialisasi kunci bersifat idempoten: jika kunci sudah ada dan valid, kunci lama dipertahankan dan tidak dibuat ulang secara sembarangan.
   - Operasi penghapusan kunci hanya terjadi atas permintaan eksplisit.

### Prinsip Desain Kunci
- **Separation of Concerns**: Logika kriptografi diisolasi sepenuhnya di dalam package `com.ipguard.authenticator.security`. UI hanya berinteraksi melalui interface `DeviceKeyManager` dan model data immutable (`KeySecurityMetadata`, `ExportedPublicKey`).
- **Defensive Error Handling**: Exception hierarkis khusus (`DeviceKeyException`, `DeviceKeyNotFoundException`, `DeviceLockScreenRequiredException`, `KeySecurityViolationException`) mencegah error internal Android Keystore membocorkan stack trace sensitif ke antarmuka pengguna.
- **Fail-Closed Security**: Jika private key mengembalikan byte array non-null pada properti `.encoded`, sistem seketika melempar `KeySecurityViolationException` untuk mencegah kebocoran private key ke runtime heap.

## 3. File yang Dibuat dan Diubah

### File Baru Dibuat (`com.ipguard.authenticator.security`)

1. **`DeviceKeyExceptions.kt`**:
   - `DeviceKeyException`: Base class untuk seluruh exception terkait operasi kunci perangkat.
   - `DeviceKeyNotFoundException`: Dilempar ketika alias kunci tidak ditemukan di Keystore.
   - `DeviceLockScreenRequiredException`: Dilempar ketika perangkat belum mengonfigurasi secure lock screen (PIN/Pola/Password) yang disyaratkan oleh kebijakan autentikasi pengguna.
   - `KeySecurityViolationException`: Dilempar jika terjadi pelanggaran postur keamanan (misalnya jika private key terdeteksi exportable).

2. **`KeySecurityLevel.kt`**:
   - Enum klasifikasi tingkat keamanan perangkat:
     - `SOFTWARE`: Kunci diemulasi dalam software platform.
     - `TRUSTED_ENVIRONMENT`: Kunci dilindungi di dalam Trusted Execution Environment (TEE).
     - `STRONGBOX`: Kunci dilindungi di dalam chip terisolasi StrongBox Keymaster.
     - `UNKNOWN`: Tingkat keamanan tidak dapat ditentukan oleh platform.

3. **`KeySecurityMetadata.kt`**:
   - Data class representasi metadata keamanan yang diekstrak dari `KeyInfo`:
     - `alias`: String nama alias kunci.
     - `algorithm`: String nama algoritma (`EC`).
     - `keySize`: Ukuran kunci dalam bit (256 bit).
     - `curve`: Nama kurva eliptik (`secp256r1`).
     - `digests`: Daftar digest yang diizinkan (`SHA-256`).
     - `purposes`: Bitmask tujuan kunci (`PURPOSE_SIGN | PURPOSE_VERIFY`).
     - `isInsideSecureHardware`: Boolean hardware backing.
     - `securityLevel`: Enum `KeySecurityLevel`.
     - `userAuthenticationRequired`: Boolean syarat autentikasi.
     - `userAuthenticationValidityDurationSeconds`: Durasi validitas autentikasi (0 = per-operation).

## 5. Kebijakan Autentikasi Pengguna

Konfigurasi parameter autentikasi dirancang untuk integrasi mulus dengan `BiometricPrompt` pada submilestone M2.3-B:

```kotlin
if (requireUserAuthentication) {
    builder.setUserAuthenticationRequired(true)
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.R) {
        builder.setUserAuthenticationParameters(
            0, // Durasi 0 = otorisasi per-operasi (wajib otentikasi biometrik setiap kali tanda tangan)
            KeyProperties.AUTH_BIOMETRIC_STRONG or KeyProperties.AUTH_DEVICE_CREDENTIAL
        )
    } else {
        @Suppress("DEPRECATION")
        builder.setUserAuthenticationValidityDurationSeconds(-1)
    }
    try {
        builder.setInvalidatedByBiometricEnrollment(true)
    } catch (_: Throwable) {
        // Fallback jika tidak didukung platform lama
    }
} else {
    builder.setUserAuthenticationRequired(false)
}
```

### Analisis Keamanan Kebijakan:
1. **Otorisasi Per Operasi (Validity Duration = 0)**:
   - Nilai durasi `0` (atau `-1` pada API < 30) menetapkan bahwa private key tidak dapat digunakan secara bebas di latar belakang. Setiap pemanggilan `Signature.initSign(privateKey)` mewajibkan token autentikasi kriptografis yang dihasilkan oleh `BiometricPrompt` (Class 3 Biometric atau Device Credential).
2. **Invalidasi Saat Pendaftaran Biometrik Baru (`setInvalidatedByBiometricEnrollment(true)`)**:
   - Jika pengguna mendaftarkan sidik jari atau wajah baru ke sistem Android (misalnya pihak ketiga yang mengetahui PIN perangkat menambahkan sidik jarinya), kunci penandatangan perangkat secara otomatis tidak dapat digunakan lagi (invalidated). Ini mencegah eskalasi akses oleh pihak kedua pada perangkat fisik.
3. **Pemberitahuan Aman Saat Lock Screen Belum Aktif**:
   - Android Keystore menolak pembuatan kunci yang mewajibkan autentikasi jika perangkat tidak memiliki PIN/Pola/Password lock screen yang aman. Kondisi ini ditangkap secara eksplisit sebagai `DeviceLockScreenRequiredException` dengan pesan edukatif tanpa crashing.

## 6. Hasil KeyInfo dan Metadata Keamanan

Inspeksi metadata dilakukan melalui `KeyFactory.getInstance(privateKey.algorithm, "AndroidKeyStore").getKeySpec(privateKey, KeyInfo::class.java)`.

### Klasifikasi Tingkat Keamanan:
Platform Android menyediakan API klasifikasi perangkat keras sebagai berikut:
- **API 31+ (Android 12+)**: `KeyInfo.getSecurityLevel()`:
  - `KeyProperties.SECURITY_LEVEL_STRONGBOX`: Dedicated tamper-resistant hardware security module (HSM).
  - `KeyProperties.SECURITY_LEVEL_TRUSTED_ENVIRONMENT`: ARM TrustZone / Trusted Execution Environment (TEE).
  - `KeyProperties.SECURITY_LEVEL_SOFTWARE`: Emulasi software di dalam Android OS.
- **API 28-30 (Android 9-11)**: Fallback kompatibel:
  - `KeyInfo.isInsideSecureHardware`: Menghasilkan `TRUSTED_ENVIRONMENT` jika true, `SOFTWARE` jika false.

### Catatan Keamanan Penting Mengenai Klaim Keamanan:
- Nilai `KeyInfo` yang diperoleh secara lokal merupakan pelaporan informasi dari sistem operasi Android lokal.
- **Klaim TEE / StrongBox lokal belum merupakan bukti kriptografis yang diverifikasi oleh server**.
- Remote Key Attestation (pemeriksaan sertifikat X.509 root Google dari hardware attestation chain) akan menjadi bagian dari fase integrasi backend server-side apabila diperlukan pada milestone berikutnya.

## 9. Bukti Non-Exportable Private Key

Sesuai kaidah keamanan kriptografi Android Keystore, private key tidak boleh dapat diekspor ke memori aplikasi. Implementasi pada `AndroidKeystoreDeviceKeyManager.kt` secara aktif menegakkan dan memvalidasi kondisi ini:

```kotlin
override fun getPrivateKey(): PrivateKey {
    reloadKeyStore()
    val entry = keyStore.getEntry(keyAlias, null) as? KeyStore.PrivateKeyEntry
    val privateKey = entry?.privateKey ?: (keyStore.getKey(keyAlias, null) as? PrivateKey)
        ?: throw DeviceKeyNotFoundException("Private key entry not found for alias: $keyAlias")

    // Penegasan keamanan kritis:
    if (privateKey.encoded != null) {
        throw KeySecurityViolationException(
            "CRITICAL SECURITY VIOLATION: Private key is exportable (encoded bytes were non-null)!"
        )
    }
    return privateKey
}
```

### Jaminan Keamanan:
- Ketika kunci dihasilkan di dalam provider `AndroidKeyStore`, objek `PrivateKey` yang dikembalikan ke memori aplikasi hanyalah sebuah referensi handle (`AndroidKeyStorePrivateKey`) yang bertindak sebagai proksi ke daemon keamanan hardware platform.
- Pemanggilan `privateKey.encoded` mengembalikan nilai `null`. Tidak ada representasi ASN.1 PKCS#8 dari private key yang pernah berada di memory heap aplikasi.
- Private key tidak pernah ditulis ke log, SharedPreferences, file sistem, atau dikirimkan melalui jaringan.

## 10. Keterbatasan yang Diketahui

1. **Keterputusan Perangkat Fisik (Physical Hardware Disconnection)**:
   - Pada saat verifikasi akhir dijalankan, perangkat fisik Samsung Galaxy A54 tidak terdeteksi pada antarmuka ADB. Seluruh rangkaian tes telah diintegrasikan ke dalam unit test JVM dan engine pengujian terprogram `DeviceKeyVerificationRunner` di aplikasi untuk verifikasi langsung di layar perangkat saat USB dihubungkan kembali.
2. **Ketergantungan Secure Lock Screen**:
   - Jika perangkat pengguna belum memiliki PIN, Pola, atau Password lock screen aktif pada sistem Android, inisialisasi kunci dengan `setUserAuthenticationRequired(true)` akan gagal dan menghasilkan `DeviceLockScreenRequiredException`. Hal ini merupakan batasan keamanan yang disengaja oleh sistem operasi Android.
3. **Absensi Remote Key Attestation**:
   - Pada M2.3-A, penentuan TEE atau StrongBox hanya dilakukan secara lokal via `KeyInfo`. Belum ada verifikasi sertifikat root X.509 hardware attestation oleh backend server. Hal ini sesuai dengan batasan ruang lingkup M2.3-A.

## 11. Temuan Keamanan (Security Findings)

1. **Pemisahan Peran Face Gate vs Keystore Authorization**:
   - Deteksi wajah ML Kit pada M2.2 dikonfirmasi **hanya berfungsi sebagai indikator kehadiran pengguna (UX presence gate)**. Fitur tersebut tidak memiliki kemampuan verifikasi identitas biometrik dan **tidak dihubungkan** ke otorisasi Android Keystore.
2. **Pencegahan Regenerasi Kunci Liar**:
   - Kunci perangkat adalah identitas permanen perangkat. Jika aplikasi membuat pasangan kunci baru setiap kali dibuka, relasi trust dengan backend akan terputus. Implementasi `ensureSigningKey()` secara ketat menjaga idempotensi.
3. **Pemberitahuan Transparan Tanpa Fallback Siluman**:
   - Aplikasi tidak secara diam-diam menonaktifkan `setUserAuthenticationRequired` jika terjadi kegagalan lock screen. Kegagalan dilaporkan secara eksplisit ke antarmuka pengguna agar pengguna mengaktifkan keamanan perangkat mereka.

## 12. Rencana dan Kesiapan M2.3-B (BiometricPrompt)

Milestone M2.3-B akan menghubungkan fondasi kriptografi M2.3-A dengan otorisasi lokal pengguna:

1. **Integrasi `BiometricPrompt` & `BiometricManager`**:
   - Menambahkan dependensi `androidx.biometric:biometric-ktx`.
   - Mengonfigurasi `BiometricPrompt.PromptInfo` dengan authenticator level `BIOMETRIC_STRONG` (Class 3) atau `DEVICE_CREDENTIAL`.
2. **Kriptografis Biometric CryptoObject**:
   - Membuka instance `Signature.getInstance("SHA256withECDSA")`.
   - Menginisialisasi dengan private key: `signature.initSign(deviceKeyManager.getPrivateKey())`.
   - Membungkus ke dalam `BiometricPrompt.CryptoObject(signature)`.
   - Menjalankan autentikasi biometrik: private key hanya dapat melakukan operasi penandatanganan payload setelah otorisasi biometrik berhasil dikonfirmasi oleh hardware.
3. **Penyimpanan Status Pendaftaran Perangkat (Device Enrollment State)**:
   - Menambahkan persistent state flag (apakah perangkat sudah terdaftar pada backend IPGuard).
4. **Persiapan Payload Enrollment**:
   - Public key dalam format `ExportedPublicKey.base64Encoded` dan fingerprint SHA-256 siap dikirimkan ke endpoint enrollment FastAPI pada M2.4.
